# Native composition acceptance

Approved October 17, 2026: Soft **Dependencies → Capabilities → Review**, additions
only, shared terminal corrections and native controls with automated coverage.
Native preview launches remain paused. This record makes no real-window,
memory-stability, external-tool, macOS/Linux desktop or release acceptance claim.

## Implemented behavior

Overview and Dependencies offer Edit packages & capabilities; the project menu
and entry strip resume the captured draft by name. The original path remains
visible throughout. Existing packages, implementations, workflow and exclusions
are locked; newly added choices can be revised. Missing/malformed/unsupported
records stay actionable without adoption or silent normalization. Catalog
defaults, actual Wally declarations, resolutions and installed files remain
separate. Package documentation and examples use the shared catalog.

Review uses the worker's checked plan and describes additions, derived packages,
missing tool pins, file actions/reasons and external operations. Generated
configuration refresh, record reformatting, downloads and new Blender scenes
are explicit impacts, not exact diffs or rollback promises. Changed source files
require explicit Reload. Dirty reload/replacement/discard defaults to Keep draft.

One composition draft and the separate New Project draft remain session-only.
Browsing, closing and explicitly opening results never switch Watch or retarget
the draft. Apply confirms its captured project and rejects a changed draft or
observed Watch state. Same-project Watch blocks Apply; Stop remains separate.
Worker source/Watch checks remain authoritative before writes.

Activity keeps captured ownership, bounded/searchable output, manual-collapse
rules and retained height. Cancellation remains pending until owned teardown;
uncertain file state is distinct from an unconfirmed teardown. Close during
Apply defaults to Keep open or offers Cancel changes and close, naming the
project and warning about partial changes. Close waits for teardown, then still
requires confirmation for another dirty draft. Teardown failure keeps the window
open. Success offers Open project explicitly.

Rendering borrows the captured record for readiness checks instead of cloning it
each frame. Actual declaration facts use a virtual list; package list/detail
panes are adjacent on wide content and stack with scrolling below 600 logical
pixels. Both drafts stay out of preferences. Window sizes, Soft palettes, native
title bar, assets/notices and CLI/Ratatui entrypoints are unchanged.

## Automated evidence

The local desktop suite passes **50 headless tests** (32 existing, two new
composition-state tests and 16 new GPUI interaction tests). New coverage includes
three-step navigation, locked original choices, reversible additions, keyboard
activation/focus, both dependency layouts, retained drafts, default-Keep reload/
close, unavailable worker explanations, stale confirmations/events, Watch
conflicts, captured operation ownership, uncertain outcomes, acknowledged close
cancellation, teardown failure, concurrent context-load guards and preservation
of each draft when the other operation closes. Startup failures allow recovery
and normal close; actual unconfirmed teardown visibly explains the close lock.
Existing Activity bounds/filtering,
height, inspection recovery, Watch controls and creation tests remain in the suite.

Headless geometry confirms that narrow details are reachable by scrolling while
footer controls remain visible. This does not establish actual pixel rendering,
contrast, Windows scaling, assistive-technology behavior or memory stability.
Strict desktop Clippy passes. Final branch review, portable-package validation
and reviewed-head/main CI delivery are recorded separately when complete.

Shared execution has 15 project-fixture and six core-draft tests. The private
[worker record](desktop-composition-worker.md) covers process/report fixtures.
Live-tool and privileged ignored tests remain unverified, not passes.

## Deferred Windows checklist — five minutes

Do not launch a preview for this checklist while native testing is paused. Resume
only after the owner authorizes a bounded native acceptance run using disposable
projects, isolated preferences and explicit tool stubs where failure is needed.

1. Check Wally/None projects, Light/Dark/System, default/minimum sizes and a long
   path; reach both dependency panes with keyboard/scrolling (60 seconds).
2. Add a package/capability; check locked choices, actual pins and file reasons.
   Change a source file and verify explicit Reload/default Keep (60 seconds).
3. Verify same-project Watch blocks Apply and Stop stays separate; another
   project's Watch remains unchanged across confirmation/Apply (60 seconds).
4. Exercise a stub failure/cancel and close during Apply: partial-change warning,
   Keep open, acknowledged cancellation, and teardown-failure refusal (60 seconds).
5. Browse/resume, filter retained output and resize/collapse Activity; preserve a
   separate dirty New Project draft, then explicitly open a success (60 seconds).
